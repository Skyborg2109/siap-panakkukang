# AGENTS.md — SIAP Panakkukang

React 19 + Vite + React Router 7 + Tailwind 3 + Zustand + Supabase. Queue-calling + display TV for Kecamatan Panakkukang. Roles are only `ADMIN`/`PETUGAS` — no loket concept in auth, no `WARGA` role.

> `README.md` / `prd.md` are stale — trust code + this file. Stale claims: 3 services (now 5), Vercel deploy (now GitHub Pages), Realtime + Replication setup (now polling), `PREFIX-001` (now `PREFIX-N`, no padding). Public warga pages (`/ambil-antrean`, `/information`, `/ikd`) were deleted — no warga UI remains.

## Commands

- `npm install` → `npm run dev` (http://localhost:5173). `npm run build` → `dist/` (`npm run preview` to check).
- `npm run lint` is oxlint, warnings-only expected (`set-state-in-effect` in polling effects). No tests, typecheck, or formatter. Plain `.js/.jsx` — don't add TypeScript.
- Deploy: GitHub Pages via `.github/workflows/deploy.yml` (push to `main`, secrets `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`; copies `dist/index.html` → `dist/404.html` for SPA fallback). `vite.config.js` sets `base: '/siap-panakkukang/'` and `main.jsx` sets `BrowserRouter basename={import.meta.env.BASE_URL}` — `<Link to="/...">` stays root-style, but **public-asset URLs must use `${import.meta.env.BASE_URL}...`**, never leading `/` (logos in `layouts.jsx`, audio in `hooks.js`).

## Dual-mode data (biggest gotcha)

- `src/lib/supabase.js`: `isSupabaseConfigured = Boolean(URL && ANON_KEY)`. Empty/missing `.env` → **demo mode** (localStorage), not an error. No `.env.example` — edit `.env` directly, restart dev server. `.env` is gitignored; deploy injects vars from GitHub Secrets.
- Every service in `src/services/` branches on `isSupabaseConfigured`. **New data access must keep both branches** — never call `supabase` from components/pages.
- Demo keys: `siap_queues`, `siap_kk_announcements`, `siap_broadcasts`, `siap_session`, `siap_services_v2` (note `v2`), `siap_requirements`, `siap_information`, `siap_announcements`, `siap_ikd`, `siap_rest`, `siap_display_images`, `siap_users`, `siap_tts`, `siap_volume`, `siap_reset_at` (round marker — quota bars count rows issued after last reset), `siap_last_call` / `siap_last_kk` / `siap_last_bc` (Display TTS dedup). Queue writes dispatch `siap:queues-changed`, master writes dispatch `siap:master-changed` (+ `storage` cross-tab) — dispatch the matching event after every local write. `withMissingSeeds()` in `masterService.js` appends new `SEED_SERVICES` without wiping admin edits.
- Prod DB: run `supabase/schema.sql` in SQL Editor — creates tables, RPCs, RLS, seeds, **and** public `display-images` bucket + Storage policies (without it, admin upload fails with RLS violation). Refresh is polling (`useRealtimeQueues(..., { pollMs: 3000 })` + storage events), **not** Supabase Realtime — no Replication setup needed. Staff mutations call `assertSupabaseSession()` first; `PGRST116` ("Cannot coerce…", i.e. RLS silently denied) maps to a relogin message. `current_role()` is SECURITY DEFINER returning `upper(role)`, so lowercase roles still pass.

## Routes / auth

- `src/routes/AppRoutes.jsx`: `/` → `/login` (no public landing). `Login.jsx` has its own chrome (don't wrap it). Admin pages wrap in `AdminShell` → `DashboardLayout` (`layouts.jsx`). No `PublicLayout` — staff-only app (petugas/admin + `/display` TV).
- `/display` is `RequireAuth(PETUGAS/ADMIN)` — TV logs in once as petugas. Linked only via sidebar quickLinks ("Monitor Antrean", `external`, new tab). Internal new-tab links must use `<Link to="/display">`, never `<a href="/display">` (`DashboardNavItem`), or the Pages `basename` is bypassed and it 404s.
- Auth: Zustand `authStore.js` from `siap_session`; demo `admin@panakkukang.go.id`/`admin123`, `petugas1@panakkukang.go.id`/`petugas123`. `counter_id`/`counter_name` are nulled compat fields — don't scope by them. Prod `createUser` only inserts a `profiles` row — the Supabase Auth user must already exist (dashboard-created); no self-signup. `App.jsx` listens for `SIGNED_OUT` and force-clears the app session so a dead login redirects to `/login` instead of failing every mutation.
- Sidebar `NavLink` needs `end` (`DashboardNavItem`) or `/admin` stays highlighted on all `/admin/*`.

## Queues

- Numbers are `PREFIX-N` via `makeQueueNumber` (`utils/date.js`); day key via `todayKey()`. 5 services in `constants.js` `SEED_SERVICES` (KTP, REKAM, IKD, KKO = KK Online Lontara+, KKB = KK Biasa). Statuses `WAITING → CALLED → SERVING → COMPLETED` + `SKIPPED`.
- Prod **must** use RPCs: `take_queue_number` (transactional, per-service `daily_quota`, granted to `anon`) and `call_direct_number` (SECURITY DEFINER, granted to `authenticated` only; the public-insert RLS policy allows only `WAITING` rows, so direct `CALLED` inserts are rejected — fallback to direct insert only on missing function, code `42883`). `nextSequenceForService` MAX+1 is demo-only. `takeQueue` is dead code (no UI imports it) — new queues enter only via petugas coupon flow (`callDirect`/`callDirectMany`).
- Timezone (proven outage): Supabase runs UTC, browsers run WITA (+8). `queue_date` is ALWAYS browser-local `todayKey()` — both RPCs take explicit `p_queue_date` (never DB `current_date`), and queue read/insert RLS policies use a ±1-day window. Otherwise 00:00–08:00 WITA writes vanish from dashboard/Display. After changing an RPC signature, `DROP FUNCTION` old+new sigs first (`CREATE OR REPLACE` rejects signature changes) and re-apply grants.
- Coupon workflow is free-order: `callDirect` creates the exact coupon number if missing, else recalls; gaps/skips allowed, no sequential guard. `callDirectMany` parses `5,6,7` / `5-8` via `parseQueueNumbers` (max `MAX_BATCH_CALL = 10`, sorted ascending) with one shared `called_at` — Display groups same-`called_at` CALLED rows as companions (chips + combined TTS `announceQueues`). Quota via `quotaFor()` (default 50, IKD 100, overridable via `daily_quota`). Progress bar counts rows issued after today's last reset (`siap_reset_at`, so reset visibly zeroes it), while RPC quota counts ALL today's rows — don't "unify" them or reset would mint fresh quota.
- Call text helpers in `constants.js` are pattern-based (survive admin prefix variants): `isLoketService()`/`callDestination()` (only `KK*` → loket, rest → ruang pelayanan), `isNameCallService()` (REKAM announced by name — Display card shows serving name big, TTS says "Panggilan atas nama …", call modal requires a name, one per call), `isSingleCallService()` (KTP & REKAM reject multi-number). Use them instead of hardcoding.
- `resetToday()` never deletes — marks active (`WAITING`/`CALLED`/`SERVING`) rows `SKIPPED` so History survives. Don't revert to `delete()`.
- Petugas panel never uses `alert()` for call flows — errors/success go through in-app `flash()` banner (`errText()` maps timeouts), every mutation wrapped in `withTimeout(20s)` (TV/kiosk browsers block dialogs). `window.confirm` only for reset. Exception: Panggil Nomor modal errors render inline via `specErr` — `flash()` sits behind the modal overlay (`z-50`). Its "Panggil Sekarang" button must stay `type="button" + onClick={handleDirect}` — as `type="submit"` it was field-proven to never fire (enabled, unobstructed, zero console output).
- Selesai/Berikutnya auto-advance: `finishAndCallNext()` (`Queue.jsx`) completes/skips ALL active numbers of the batch at once (batch chips are display-only, not selectable), then `callDirect`s (highest batch `sequence`)+1 and selects it (e.g. IKD-2,3,4,1 → IKD-5). Selesai = COMPLETED, Berikutnya = SKIPPED. `recallTarget()` re-CALLEs the whole batch with one shared `called_at` to keep Display grouping. Quota-exhausted still finishes the batch but skips the advance.
- Anti-menumpuk guard (`handleDirect`): a NEW number while `CALLED`/`SERVING` exist shows a `specPending` confirm box (**Selesaikan & panggil** / **Lewati & panggil**, via `handleDirect(null, completeQueue|skipQueue)`) that finishes actives first — no pile-up, but sequential numbers (KTP-23 → KTP-24) still work. Re-calling already-active numbers (all requested ⊆ active, e.g. via chip) skips confirmation; idle batch (`5,6,7` for IKD/KKO/KKB) still allowed. Modal shows an amber box when actives exist (`specActives`). Don't loosen without approval — a pile-up of a dozen actives (KTP-13..KTP-22) was a fixed bug.
- "SUDAH DIPANGGIL" chips (`handled`) list today's `CALLED`/`SERVING`/`COMPLETED` (not `SKIPPED`) **filtered to the current round** — `created_at`/`called_at`/`updated_at >= siap_reset_at` (same marker as the quota bar). Required because `resetToday()` leaves `COMPLETED` rows untouched, so without the round filter completed chips survive reset. Recalling an old number by typing refreshes its `called_at`/`updated_at`, so its chip reappears in the new round. Container is `max-h-44 overflow-y-auto` so the card doesn't stretch.
- Services can't be hard-deleted with queue rows (`queues.service_id on delete restrict`): Hapus button checks `getServiceQueueInfo()` first (History defaults to today, but the FK counts **all** dates) and confirms permanent delete including history (`deleteServiceWithHistory`); `deleteService` falls back to `is_active=false` on FK error `23503` — don't force-delete, history/statistics depend on it.
- Three announcement channels — don't confuse: `announcements` = bottom ticker; `kk_announcements` (`callKKCase`/`getLatestKK`, BR-09, no number) and `broadcasts` (`sendBroadcast`/`getLatestBroadcast`, spontaneous) = ~20-sec banner + audio each.

## TTS / display

- TTS `useSpeech()` (`hooks.js`): `id-ID`, toggle in `siap_tts`, volume in `siap_volume` (max 1.0 — browser cap, no volume UI), opening sound → announcement 2x → closing sound. Audio filenames contain a space (`opening sound.mp3`) — don't rename without updating `hooks.js`. Display stays silent until first user gesture (autoplay policy; dedup via `siap_last_*` in localStorage so reopening doesn't re-announce).
- Display slideshow (`Display.jsx`): one slide per image category (`CATEGORY_ORDER`/`CATEGORY_META`, order = pimpinan → petugas dukcapil → alur — intentional); staff photos of a category render together in one row, `alur` one image per slide, uncategorized grouped into a "Dokumentasi" slide. Text lives only in the ticker — the single `info` slide is just the empty-state fallback when no images exist.
- Admin upload must pass the real `File` to `uploadDisplayImage` (Storage upload in prod); base64-only silently takes the demo branch. `getAllDisplayImages` maps `url` via `imageUrl()` — don't return raw `file_path`.
- Rest image (`displayService.js` `getRestConfig`/`saveRestConfig`/`uploadRestImage`, `isRestNow()` in `utils/date.js`): ONE `display_contents` row `key='rest'` with JSON `{enabled, start, end, image}` — no migration needed; prod image goes to Storage `display-images/rest/...` (not `display_images`, to dodge the category check), demo keeps base64 in `siap_rest`. Config lives in the **petugas panel** (`Queue.jsx` "Notifikasi Istirahat" card, status badge shows live `Sedang tampil di TV` — label recomputes each 3s poll render), NOT the admin DisplayImages page. Prod needs latest `schema.sql` re-run: `display_contents key='rest'` + Storage `rest/*` are writable by `PETUGAS` (scoped policies `staff manage rest content` / `staff * rest image`), everything else display-related stays ADMIN-only. Display swaps the left slideshow for the rest image during the window (overnight wrap supported, start inclusive/end exclusive) while queue cards + ticker keep running.
- Multiline admin content (IKD/Information) may contain literal `\n` — render with `.replace(/\\n/g, '\n')` + `whitespace-pre-line` (as `admin/Information.jsx` does).
- UI: `GovLogos` from `layouts.jsx`; theme navy `#0b1220` + `orange-600`; reuse `btn-primary`/`card`/`input`/`badge` from `index.css`.
